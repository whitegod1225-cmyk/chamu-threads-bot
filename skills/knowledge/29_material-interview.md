# 29_material-interview.md ── 荒素材→note記事化フロー

> **このファイルの使い方**：ちゃむから「断片的なメモ・体験談・思いつき」が提供されたとき、
> それをnote記事の素材として整理するための前処理フロー。
> `/note-article-seller` `/note-seo-writer` `/note-writer` `/writer` `/kapi-writer` で
> 「素材が荒い」「まとまっていない」「メモだけど」と感じたときに参照する。

---

## このフローを使うタイミング

| 使う | 使わない |
|------|---------|
| 「こんなこと思ってる」「メモだけど」「箇条書きで書いた」 | テーマ名だけ指定（素材なし） |
| 体験談・エピソードが断片的で記事の方向が見えない | 素材が既に整理されている |
| ちゃむが「何を言いたいか」自分でも整理しきれていない | Threads投稿（短文・速度優先） |
| 感想・感情が多く、ノウハウになっていない | 方向確認が不要と明示された |

---

## STEP1：素材の4分類

受け取った素材を以下4つに分類して整理する。記事化の前に必ず行い、混同したまま書き進めない。

| 分類 | 内容 | 記事での扱い |
|------|------|------------|
| **実際に起きたこと** | ちゃむが体験した・現場で見た・確認できること | そのまま使える |
| **意見・感想・判断** | 「こう思う」「こう感じた」と述べていること | 主語を「私は」にして使う |
| **仮説・推測** | 「たぶん〜」「〜かもしれない」レベル | 「〜ではないかと感じている」で使う |
| **まだ足りない情報** | 書くために必要だが素材にないこと | ちゃむに確認するか、その情報を使わない構成にする |

→ 「実際に起きたこと」と「仮説」を記事内で同格に書かない。
→ 「まだ足りない情報」が記事の主張に直結する場合は確認してから進む。

---

## STEP2：核心を探す5つの問い

素材から記事の「核」を見つけるために自問する。

1. **ちゃむは何を問題だと感じているか？**
2. **どうなれば「解決」だと考えているか？**
3. **何を見て・体験して、そう判断したか？**
4. **その判断は、どんな場面のどんなママに使えるか？**
5. **読んだママが「明日から」できる確認・行動・判断基準は何か？**

→ 5問のうち3問以上答えられない場合は素材が不足している。ちゃむへの確認または素材追加を促す。
→ 主張が相反していて「どちらを書くか」で記事が大きく変わる場合は、方向案を2〜3個提示して選んでもらう。

---

## STEP3：方向確認フロー（2ステップ）

素材から記事を作るときのデフォルト動作。

### STEP3-1：方向確認（400字以内で提示）

本文を書く前に、以下を簡潔に示してちゃむの確認を取る。

```
1. このメモで伝えたいこと（主張1文）
2. 誰の・どんな困りごとに役立つか（読者と場面）
3. ノウハウとして取り出す内容
   （実践手順 / 判断基準 / 失敗回避 / ケース別対応 など）
4. 記事の流れ（見出し案3〜5個）
```

**確認後の分岐**：

- 「その方向で」「OK」「書いて」→ STEP3-2へ
- 修正あり → 反映してSTEP3-2へ
- 「確認なしで本文まで」と指定された場合 → STEP3-1を省略して直接STEP3-2へ

### STEP3-2：本文生成

方向確定後、通常の note 生成フロー（`/note-article-seller` / `/note-seo-writer`）に引き継ぐ。
ちゃむのペルソナ・文体ルール（`03_writing.md`）・感情設計（`24_note-emotion-design.md`）を適用する。

---

## STEP4：感想を「行動・判断」に変換する

ちゃむの素材には感想・感情が多い。そのまま記事にすると「共感で終わる記事」になる。
以下の変換フレームで、読者が「明日から使える」レベルに具体化する。

| 素材にある表現 | 変換のための問い |
|------------|----------------|
| 「〇〇って大事だと思う」 | →何を見ればわかる？どう確認する？ |
| 「〇〇はダメ」 | →何がどうダメ？代わりに何をする？ |
| 「もったいない」 | →何をやっていない？最初に何から変える？ |
| 「〇〇が必要だと感じた」 | →どんな場面で？どんな順番で？何があればOK？ |
| 「〇〇してあげたい」 | →具体的に何と言う？どう動く？ |

→ ちゃむの育児・保育テーマでは特に「〇〇な気持ちになったら、こう言えばいい」まで落とすと使える記事になる。
→ 手順にしにくい素材なら「判断基準」「NG/OK比較」「場面別の考え方」の形にする。無理に「〇〇の3ステップ」にしない。

---

## STEP5：事実・体験の扱いルール（厳守）

以下はHARD GATESと同格に扱う。違反があれば書き直す。

- ちゃむが体験していない出来事を「私が〜した」として書かない
- 仮説・推測を「〜が分かっています」「〜です」と確定形で書かない
- 体験の「回数・期間・人数・効果」を補わない（素材にある数字だけ使う）
- 保育現場の話を、ちゃむが直接関わっていない場合は「現場ではよく〜」「よく相談を受けた」など主語を明確にする
- Claudeが提案した内容を「ちゃむがやってみた」として記事に入れない
- 説明用に「たとえば〜」と仮の例を使う場合は「たとえば」「仮に」「作例」と明示する

---

## STEP6：Threads投稿素材に使う場合（短文版）

荒素材からThreads投稿（200〜350字）を作る場合は、STEP3の確認フローを省略してよい。
代わりに以下の2点だけ確認して進む。

1. **1行目で使える「核心」は何か**（STEP2の問い⑤から逆算）
2. **感想を映像・行動に変換できているか**（STEP4の変換フレーム適用）

→ `/writer` の STEP2「フック生成」の前に本ステップを差し込む。
